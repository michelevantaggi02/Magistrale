In the previous chapters, we introduced various supervised learning algorithms with
the aim of estimating, from the data, a model capable of mapping two random variables, i.e., t (the output variable) and x (the feature vector). These two variables are
characterized by a joint distribution p(t, x) which is unknown and of which we have
information only through a set of samples (the dataset) that are realizations of it. In
detail, we have access to a dataset, called training set Dtraining consisting of samples
{(x(0) , t(0) ), (x(1) , t(1) ), . . . , (x(N1 −1) , t(N1 −1) )} which are realizations of the joint distribution, i.e., (x(i) , t(i) ) ∼ p(x, t).
Using the training data, we try to estimate a model that relates x and t and approximates well the unknown relationship that exists between the two variables. We saw
that, in some case, it is sufficient for us to directly estimate the function t = f (x) (as
in the case of discriminant functions), other times we instead try to model the posterior
distribution of the output variable p(t|x) (as in the case of discriminative models). We
have also seen that we can directly make inference about the joint distribution p(x, t)
with approaches based on generative models.
Regardless of the type of strategy we use, the goal is always the same: to minimize
a cost function computed on the training set data. In general, the cost function, or
Loss function, expresses a measure of similarity between the predicted value t̂ and the
true value of supervision t. We have, for example seen the quadratic loss for Linear
regression:
L(t, t̂) = L(t, hw (x)) = L(t, wT x) = (t̂ − t)2

A good model, in fact, guarantees a low test error and not too much different from

the test set we say we have overfitting. Vice versa, if the error on training sets is high

to capture the characteristics of the data generation process: in this case we speak of
underfitting.
A Machine Learning model acts on the trainable parameters w and, once optimized,
achieves a certain test error. What can we do if we are not satisfied with this error? In
general, it is possible to act on the structure and definition of the hypothesis function

on the characteristics of the hypothesis function. We can, for example:
• Choose the structure of the hypothesis function. For example, we may choose to

• Choose whether and which basis function to use;
• Choose what importance to give to the regularization hyper-parameter (as we will

• Choose whether to perform a polynomial expansion and of what degree;
• Choose the form of the class conditional distributions for generative models;
• Choose the number of neighbors to consider in K-NN classifier;

Each of these choices has an impact on the Complexity of the model or, alternatively,
on its Degree of freedom (DoF), i.e., , its representational power. If we notice that a
model gives very high errors on both training and test sets, it means that it is rigid (low
complexity). To increase its flexibility we can, for example, use more basis functions or
reduce the effect of regularization. However, increasing the complexity too much could
result in models that follow the noise of the training data, leading to overfitting. To
better understand this concept, we can draw the training and test error curves as the
complexity of the model varies (see Figure 9.1)
From the figure we can see that, as the degrees of freedom of the model increase, the
error on the training decreases (the model has more flexibility and is free to follow the
training data). However, although initially also the test error decreases, by increasing
the complexity, at some point it will tend to grow since the model begins to follow the
noise and no longer focuses on the pattern hidden among the data.
It makes sense to ask ourselves what the best strategy is for identifying the best degree
of complexity. As we have seen, to do this it is necessary to evaluate the performance
of the model on data never seen during training.
A first option would be to train the model on Dtraining with a specific configuration
of the degrees of freedom (hyper-parameters and design choices), test it on Dtest , and
reiterate if we are not satisfied with the performance. In this way, however, the test
dataset does in fact play a role in determining the hyper-parameters: we actively use it
to determine them, and so they necessarily take values that ”work” well with respect to

samples to test the generalization capabilities of the final model. For this reason, we
need to consider a third set, known as Validation Set, to be used to find the best
configuration with respect to the complexity of the model (see Figure 9.2).
The procedure that is used to choose the configuration of the degrees of freedom of
a model (and thus its complexity) is known as Model Selection. The procedure that
instead aims at evaluating the performance and the generalization capabilities of the
model once both the trainable parameters and the hyper-parameters that control
its complexity have been optimized (the latter using the model selection procedure), is
known as Model Assessment.
Before introducing the strategies we can use to perform model selection and model
assessment, let us give some more details about the concept of model complexity and,
in particular, the trade-off between rigidity and flexibility.

9.1

Bias-Variance Decomposition

As we said in the previous section, when we define the machine learning model to be
used, we make choices and assumptions that affect its structure and thus the result we
obtain. As mentioned above, our ultimate goal is to obtain a model that works well on
data that have never been used either to find the trainable parameters, or for the hyperparameters and model choices that determine the degrees of freedom (complexity): the
test data.
The purpose of the algorithm is then to estimate the ”true unknown” model by
using the training data. When we design the algorithm, as we already mentioned,
we make some choices that influence its flexibility. For example, if we choose to use
linear regression, we are deciding that the ”unknown” model is characterized by a linear
relationship between input and output. These assumptions clearly entails an error with
respect to the true model, an error that will be higher the more the assumption deviates
from reality. If the assumptions are too strong, we can think of relaxing them and
increase the complexity of the model. However, in this case we risk, as we already saw,
to incur into overfitting. To characterize these scenarios, we define two concepts:
• Bias: the error deriving from assumptions that are too strong and ”unrealistic” (or
in any case not completely true) that the lerning algorithm makes. More generally,

9. Model Selection and Model Assessment

135

its the error the arises from using a model with a reduced number of degrees of
freedom.
• Variance:the error associated with the sensitivity of the learning algorithm to
noise in the training data.
A model with high bias and low variance is a rigid model with few degrees of freedom,
while a flexible model (with many degrees of freedom) has high variance and low bias.
Having a high error due to bias leads us to a condition called Underfitting, as the
error is generated by the amount of relevant information contained in the data that is
discarded due to the low representative power of the model. Instead, a high error because
of the variance is said Overfitting and it depends from having modeled also the noise
of the training set (that, in practice, translates in a model that ”learns to memorize”
the training data). In this second case, we are, in fact, modeling information that is not
relevant for inference.

Approaches for Model Selection and Model Assessment

9.2.1

Model Selection

From the previous sections we have understood that the choice of the flexibility or
complexity of the model is fundamental. To do so, we have the possibility to act on
several aspects. In particular, the DoFs of a model can depend on:
• Type of algorithm and hypothesis function hw (x). For example, we could
choose the hypothesis function of Linear Regression, Ridge Regression, Neural
Networks, etc.... Each hypothesis function carries with it assumptions that impact
the flexibility of the model;
• Hyper-parameters of regularization. For example, the λ hyper-parameter of
Ridge Regression or Lasso Regression that we will see in the next chapter;

9. Model Selection and Model Assessment

139

• Hyper-parameters specific to the chosen algorithm. For example, the number of K neighbors of K-NN classifier;
• Degree of polynomial expansion of features;
• Number and type of Basis functions;
• Choice of the number of parameters w of the algorithm. In linear regression, for example, by increasing the basis functions we are in fact increasing the
number of parameters to be learned and thus the flexibility of the model. With
neural networks, as we will see, we will have even more flexibility with respect to
the choice of vector size w .
• ...
The best DoF configuration for the model is the one that guarantees the lowest error
on the data set used, i.e., the point shown as ”Best Model” in the graph in Figure 9.3.

final model (the one with both parameters w , and hyper-parameters and design choices

the best degree of complexity for our problem.

Role of the number or training samples
From the point of view of the impact on the trend of the training and the test errors, also
the number of training samples plays a fundamental role and can therefore be object of
evaluation through model selection. Typically, having fixed the complexity of the model
(therefore the various hyper-parameters, the design choices, etc...), if this is trained with
a reduced number of samples we expect a very high error on the test and very low on
the training: the loss function used during training depends on few samples and it is,
therefore, easier for the model to set its parameters w to guarantee a low error. However,

143

with little experience is clear that the model perform poorly on data never seen. By
increasing the number of samples of the training set, the model has more and more
elements to take into account during the optimization and it will be more difficult to
reduce the estimation error for all of them. On the other hand, with more experience
it is easire to understand the structure of the data generation process and therefore to
generalize better on samples never seen: the test error therefore will decrease (you see
Figure 9.5). It is therefore clear that it is always worthwhile to increase the number
of samples in the training set. However, since acquiring the dataset is expensive, this
type of study is carried out to get an idea of the real advantage that we could obtain by
acquiring more data. In fact, training the model using more and more portions of the
training set is equivalent to simulate the situation in which we increase the size of our
dataset.

9.2.2

Model Assessment

Once we have trained the model and identified the best DoF configuration, we can verify
the performance of our model on never observed data, i.e., the Assessment phase. For
this phase we can use the same techniques seen for the model selection, that is Fixed
Test Set, K-Fold Cross Validation and Leave-one-out. In the case of fixed test set,
it is sufficient to evaluate the performance of the final model on the split of the dataset
reserved for testing. In this case, as previously said, it is better to use the model trained
